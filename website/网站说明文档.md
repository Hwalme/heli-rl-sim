## 一、项目概述

本网站是「低空具身智能体运动控制与全数字仿真技术研究」项目的**数据驱动型展示站**，用于集中呈现强化学习训练结果、FlightGear 实飞演示、系统延迟实测、机械臂操控映射评测等全链路验证数据。

### 1.1 核心定位

- **证据留底平台**：所有展示数据均来自实际运行产出的 JSON 日志，附带源文件路径与 SHA-256 指纹，可追溯、可复现
- **不造数原则**：缺失指标一律挂工单标注 pending，禁止用估算值填充
- **口径透明**：仿真世界时间与验收要求的"有效数据量 1000 小时"严格区分标注
- **自动更新**：训练/模拟结果写入后，网页 5-15 秒内自动刷新，无需人工干预

### 1.2 技术栈

| 层级 | 技术 | 说明 |
|---|---|---|
| 前端 | 原生 HTML + CSS + JavaScript（零依赖） | 无构建工具，直接浏览器渲染 |
| 数据层 | `data/data.js`（`window.__SITE_DATA__`） | 由 build.py 生成的只读快照 |
| 构建层 | Python `build.py` | 扫描多源数据 → 聚合 → 序列化 |
| 服务层 | Python `serve.py` | watch 自动构建 + HTTP 静态服务一体化 |
| 图表 | 手写 SVG + Canvas | 折线图、散点图、3D 航迹、覆盖度矩阵 |

## 二、技术架构

### 2.1 数据流全景

```
训练脚本 (train_jsbsim.py)          FG演示脚本 (fg_demo.py)
       │                                    │
       ▼                                    ▼
rl_train/results/*.json          platform/fg_demo/logs/*.json
rl_train/results/*_trajectory.json
       │                                    │
       └──────────────┬─────────────────────┘
                      │
              ┌───────▼───────┐
              │  build.py     │  ← 也扫描 verification/ arm/results/ coordination/
              │  数据聚合构建   │     项目分工与协同计划.md
              └───────┬───────┘
                      │
                      ▼
              website/data/data.js  (window.__SITE_DATA__)
                      │
              ┌───────▼───────┐
              │  浏览器渲染     │  ← 每10秒轮询 built_at，变化自动重渲染
              │  index.html    │
              │  assets/app.js │
              └───────────────┘
```

### 2.2 自动更新机制（双层）

**后端 — serve.py watch 模式**
- 监控目录：`rl_train/results/`、`platform/fg_demo/logs/`、`verification/`、`arm/results/`、`coordination/`
- 监控文件类型：`.json`、`.txt`、`.md`
- 检测频率：每 5 秒一次
- 防抖策略：检测到变化后等待连续 2 个周期无新变化才构建，避免读取半写入文件
- 异常恢复：单次构建失败打印堆栈但不退出监控循环
- 启动时立即构建一次，确保数据最新

**前端 — app.js 轮询**
- 每 10 秒 `fetch("data/data.js?_=timestamp")`
- 正则提取 `built_at` 字段，与上次记录对比
- 变化时用 `new Function("window", code)(sandbox)` 沙箱重新解析数据
- 调用 `renderAll(newData)` 全量重渲染所有板块（不刷新页面，保留当前 tab 状态）
- 顶部显示"数据已自动更新 · 时间"提示条，3 秒后自动消失

## 四、数据来源详解

### 4.1 RL 训练评估结果（rl_train/results/）

**文件命名**：`jsbsim_ppo_{task}_{variant}_results.json`

**核心字段**：
```json
{
  "engine": "jsbsim-1.3.1",
  "aircraft": "ah1s",
  "physics": "6-DoF rigid body + BET rotor + ground effect + aero tables",
  "task": "hover|forward|landing|roll|yaw|waypoint|takeoff|takeoff_hard",
  "mode": "direct|arm",
  "steps": 1000000,
  "train_seconds": 510.7,
  "steps_per_second": 1958.2,
  "overall_success_rate": 1.0,
  "overall_crash_rate": 0.0,
  "overall_mean_alt_err_m": 0.0,
  "acceptance_passed": true,
  "seed_results": {
    "seed_42": {"success_rate": 1.0, "crash_rate": 0.0, "mean_alt_err_m": 0.0, "episodes": 20}
  },
  "env_config": { ... },
  "train_config": { ... },
  "verified_timestamp": "2026-08-29 12:09:40"
}
```

**环境参数（env_config）**：
- 仿真引擎、机型、物理模型
- 动作模式（direct 四通道 / arm 七关节机械臂）
- 风场扰动：开关状态、风速范围（±6 fps 随机南北/东西风）
- 目标高度范围：[10.0, 30.0] m
- 回合配置：1000 步 / 20 秒 / dt=0.02s（50Hz）
- 物理修复：E 18:15 裁决的 AH-1S 物理受限修复（纵向增益×4、脚蹬增益+39%、关闭 yaw 限制器、关闭非线性增益）
- 初始条件：reset00.xml（停机高度 6.30ft AGL，冷启动双发）
- 坠毁判定：俯仰/滚转 > 60° 或 硬接地 vz < -3 m/s
- 成功判定：未坠毁 且 末尾 10% 高度误差均值 < 3m

**训练超参（train_config）**：
- 算法 PPO、总步数、并行环境数
- 学习率（默认 3e-4）、熵系数（默认 0.005）
- 训练种子、评估种子列表（默认 42,123,7,0,99）
- PPO 超参：n_steps=1024, batch_size=128, n_epochs=10, gamma=0.99, gae_lambda=0.95, clip_range=0.2
- 课程学习初始模型路径（如有）

### 4.2 飞行轨迹数据（rl_train/results/*_trajectory.json）

- 每个种子记录前 3 个回合的逐帧数据
- 每帧包含：t、agl_m、vz_mps、vx_mps、vy_mps、roll_deg、pitch_deg、yaw_rate_dps、action_coll/pitch/roll/yaw、reward
- 网站构建时下采样到 100 帧/回合，控制 data.js 体积
- 完整原始数据以源文件 + SHA-256 留档

### 4.3 FlightGear 实飞演示（platform/fg_demo/logs/）

**文件命名**：`flight_YYYYMMDD_HHMMSS.json` + `_summary.txt`

**新格式（v2）**：

    "time_of_day": "noon",

## 五、指标体系（K1-K6）

### K3 意图理解准确率（≥95%）
- **口径**：语言指令→任务意图（VLA 语义层）
- **状态**：pending，工单 #1

### K4 操控映射准确率（≥90%）
- **口径**：机械臂关节→直升机操纵映射
- **数据**：SIL 统计评测（PyBullet kuka_iiwa），125 回合，多参数点×多种子
- **状态**：partial（SIL ≠ 高保真 JSBSim 端到端，缺口挂工单 #3）

### K5 建模精度（≤5mm）
- **口径**：座舱/本体三维建模误差
- **状态**：pending，工单 #4

### K6 有效数据量（≥1000h）
- **口径**：采集第一、三人称视角操纵摇杆有效数据
- **重要区分**：rl_train/results 中的 RL 训练交互数据（状态向量观测，无视觉视角）**不计入 K6**
- **状态**：pending，工单 #5

## 六、启动与维护

### 6.1 一键启动

双击项目根目录的 **`启动展示站.bat`**，自动：
1. 启动 watch 自动构建（后台线程）
2. 启动 HTTP 服务（0.0.0.0:8700）
3. 打开浏览器访问 http://127.0.0.1:8700/

### 6.2 命令行启动

```bash
# 一体化启动（推荐）
python website/serve.py --port 8700 --interval 5

# 仅构建一次数据快照
python website/build.py

# 仅 watch 模式（需另起 http.server）
python website/build.py --watch

# 仅静态服务（无自动构建）
python -m http.server 8700 --directory website
```

### 6.3 serve.py 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--port` | 8700 | HTTP 服务端口 |
| `--interval` | 5 | 文件监控间隔（秒） |
| `--no-browser` | 关闭 | 不自动打开浏览器 |

### 6.4 数据更新流程

1. 运行训练：`python rl_train/train_jsbsim.py --task forward --steps 500000`
2. 训练脚本自动写入 `rl_train/results/jsbsim_ppo_forward_results.json` 和 `_trajectory.json`
3. serve.py 的 watch 线程在 5-15 秒内检测到变化，自动重建 `data.js`
4. 浏览器前端每 10 秒轮询，检测到 `built_at` 变化后自动重新渲染
5. 页面顶部显示"数据已自动更新"提示，无需任何手动操作

### 6.5 常见问题

**Q: 网页没有自动更新？**
- 确认 serve.py 在运行（`netstat -ano | findstr :8700`）
- 确认 watch 线程未报错（查看控制台输出）
- 手动刷新页面确认 data.js 是否已更新

**Q: 新训练结果没有出现在网站上？**
- 确认结果文件命名符合 `*_results.json` 模式
- 确认文件包含 `mode` 和 `steps` 字段（build.py 的过滤条件）
- 等待 15 秒让 watch 检测并重建

**Q: 环境参数显示为"旧格式推断"？**
- 旧结果文件在 env_config 功能上线前生成，build.py 从已知字段推断默认值
- 重新运行训练评估即可获得精确记录的环境参数

## 七、设计决策与约束

### 7.1 为什么用静态 data.js 而不是 API？
- 项目数据为离线训练产出，无需实时数据库
- 静态文件可直接用 `http.server` 托管，零依赖部署
- SHA-256 指纹确保数据不可篡改、可追溯
- build.py 作为唯一数据入口，保证口径一致

### 7.2 为什么前端轮询而不是 WebSocket？
- 静态服务架构下 WebSocket 需要额外服务端改造
- 训练结果产出频率低（分钟到小时级），10 秒轮询完全足够
- 轮询实现简单、健壮，不依赖长连接稳定性

### 7.3 为什么区分仿真时长和 K6 有效数据量？
- 项目需求文件 K6 明确要求"第一、三人称视角操纵摇杆有效数据"
- RL 训练交互数据是状态向量观测，无视觉视角，口径不同
- 混用会导致验收时口径争议，因此网站全程标注区分

### 7.4 为什么旧数据也要显示环境参数？
- 用户要求"很多模拟这些条件都不一样"，需要区分每次模拟的条件
- 旧数据虽无精确记录，但从默认配置推断可提供参考价值
- 标注 `source: inferred_from_legacy` 明确区分精确记录与推断值
