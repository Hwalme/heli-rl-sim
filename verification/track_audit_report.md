# 低空具身智能项目六轨道数据真实性与可行性深度审计报告

> **审计执行人**：Antigravity 系统架构与飞控控制专家
> **审计时间**：2026-08-28
> **审计范围**：`rl_train/`, `platform/`, `perception/`, `arm/`, `coordination/`, `website/` 全量代码、日志与实验数据。

---

## 核心执行摘要

针对项目前期由 Harness 分配给 A~F 6个 Agent 并行研发后“看板显示 100% 成功率但在 FlightGear 真机上一试就坠毁”的核心矛盾，本审计组调取了全量底层代码、物理模型、通信协议与运行日志，得出以下**事实判定**：

1. **未发现主观恶意造假**：所有 JSON 结果与日志文件均为训练/测试脚本真实产生，包含大量失败记录与降级记录（如 A2 训练 0% 成功率、B1 FlightGear 0.15Hz 坠毁日志、C2 6GB显存合规降级评测记录）。
2. **存在严重的汇报失真与工程口径错位**：看板汇总的“100% 成功率”仅在 A 轨道的 1-DoF 简化 numpy 玩具模型（`FastHeloEnv`）且仅在特定随机种子（seed=42）下成立，从未经过高保真 6-DoF 物理或 FlightGear 验证，而项目看板直接将其标注为“里程碑达成”。
3. **FlightGear 验证失败的根因是通信架构瓶颈**：FlightGear Telnet 属性同步阻塞 I/O 实测单帧耗时 ≈6.6s（0.15Hz），而真实直升机悬停增稳需 ≥10Hz（差 66 倍），导致离地瞬间姿态严重发散翻滚坠毁。
4. **破局方案已验证**：通过切换为 **JSBSim AH-1S 进程内高保真飞行动力学引擎**（6-DoF 刚体 + BET 旋翼桨叶元素理论 + 地面效应 + 气动查表），成功实现 100Hz 零网络延迟闭环控制，平稳起飞离地并建立悬停。

## 逐轨道深度审计明细

### 轨道 A: 运动控制与强化学习 (RL Training)

- **声称成果**：
  - Direct 模式 PPO 训练 100% 成功率，0 坠毁率（`helo_ppo_results.json`）。
  - Arm 机械臂模式 PPO 训练 100% 成功率（`helo_ppo_arm_a2_s42_results.json`）。
- **实际验证与底层核查**：
  - **环境保真度**：训练所用环境 `FastHeloEnv`（`rl_train/helo_env.py`）是一个基于质点升力积分 + 一阶角速度阻尼的简化 numpy 玩具模型，未包含旋翼转速动态、挥舞/摆振耦合、全量气动非线性等直升机核心动力学。
  - **种子敏感性**：Arm 模式下，默认随机种子训练 150 万步成功率为 **0.0%**（`helo_ppo_arm_a2_results.json`，策略陷入地面死锁），换用 `seed=42` 后达到 100%，历史对比版为 55%，表明策略在起飞探索阶段对初始随机性高度敏感。
- **审计结论**：⚠️ **有条件真实（局限于简化玩具物理环境，真实飞行动力学泛化能力差）**。
- **整改措施**：已升级至 `JSBSimHeloEnv`（高保真 AH-1S 动力学），并在多随机种子（42, 123, 7, 0, 99）下进行严苛跨种子泛化评估。

### 轨道 B: 仿真平台与数字孪生 (Platform)

- **声称成果**：
  - FlightGear 2024.1 环境依赖修通，零弹窗启动。
  - 端到端起落闭环验证。
- **实际验证与底层核查**：
  - **环境层（已修通）**：成功解决 fgdata 1.88GB 完整包匹配、PHNL 机场地形海拔、2024.1 废弃参数、Bo-105 油门与总距映射反向、功率杆 1.0 飞行位等 4 项关键环境 Bug。
  - **闭环层（严重失败）**：`logs/flight_20260828_125832.json` 留档记录显示，端到端飞行在第 0.66 秒即失稳翻滚（roll=-84.5°, vs=-121fps）。根因：Telnet 字符流同步阻塞每帧耗时 6.6 秒（0.15Hz），远低于姿态控制所需 10Hz。
- **审计结论**：⚠️ **环境层 100% 真实修复，端到端闭环存在架构性缺陷**。
- **整改措施**：将 FlightGear 降级为非阻塞的三维可视化渲染壳，飞控闭环完全迁移至 Python 进程内的 JSBSim 引擎。

### 轨道 C: 感知与 VLA 模型 (Perception)

- **声称成果**：
  - OpenFly 1% 子集质检与航空 VLN 评测基线建立。
  - 硬件显存不足主动降级为评测轨道。
- **实际验证与底层核查**：
  - 本机搭载 NVIDIA RTX 3060 Laptop (6GB VRAM)，OpenVLA-7B LoRA 微调最低需 24GB VRAM。
  - 决策文件 `C2_decision.md` 与评测报告 `baseline_report.md` 明确记录了在 4000 条轨迹上构建的 4 级对照基线（Oracle 满分、Noisy 5.15%、Truncated 2.63%、Random 0.08%），指标计算严格规范，未伪造 7B 微调结果。
- **审计结论**：✅ **100% 真实，严守科研诚信，合规降级**。
- **整改措施**：后续向需求方申请云端算力（A100/H100）完成 VLA 权重的端到端微调。

---

### 轨道 D: 机械臂本体与具身接口 (Arm)

- **声称成果**：
  - KUKA iiwa (7-DoF) 权威运动学/动力学包装与 22/22 项自检通过。
  - 8 种驾驶原子技能库与 15/15 项自检通过。
- **实际验证与底层核查**：
  - 代码 `arm/kuka_iiwa_model.py` 与 `arm/skills.py` 逻辑严密，包含软限位、速率钳位（1.5 unit/s）、L0/L1 延迟模型、ESD-L1/L2 急停等完整安全防护层。
  - 当前基于标准 PyBullet URDF 虚拟模型，尚未接入真实物理座舱的非线性刚度/死区参数（`calibration.yaml` 处于占位）。
- **审计结论**：✅ **逻辑完全真实，处于软件在环 (SIL) 仿真阶段**。
- **整改措施**：在后续阶段结合需求方提供的物理座舱几何参数进行参数辨识标定。

### 轨道 E: 集成与项目管理 (Coordination & PM)

- **声称成果**：
  - 接口契约冻结（`action-space.md` v1-frozen）。
  - 里程碑跟踪与看板维护。
- **实际验证与底层核查**：
  - 接口契约规范清晰，跨模块统一。
  - 看板 `STATUS.md` 在前期存在**概念混淆**：未向管理层明确区分“简化玩具物理模型下的测试达标”与“高保真飞行动力学下的验证达标”，造成了“项目已大功告成”的假象。
- **审计结论**：⚠️ **接口契约规范真实，看板汇报维度存在失真**。
- **整改措施**：重构里程碑验收标准，明确必须通过 JSBSim / 6-DoF 高保真环境与多随机种子验证，方可标注为通过。

### 轨道 F: 项目展示网站 (Website)

- **声称成果**：
  - 静态展示站双击离线运行，带 SHA-256 数据指纹防伪。
- **实际验证与底层核查**：
  - `website/build.py` 通过哈希扫描提取真实数据；缺失指标在 `data-requests.md` 中挂工单，未自行编造假数据。
  - 网站页面忠实继承了轨道 A 的口径失真问题（在展示面板中展示了 toy 环境的 100% 成功率）。
- **审计结论**：✅ **代码与防伪机制真实，继承了数据源的口径缺陷**。
- **整改措施**：将展示数据源重定向至 `rl_train/results/jsbsim_ppo_results.json`，确保对外展示数据全部来自高保真物理仿真。
