## 1. v2 失败证据与"趴地"根因诊断

### 1.1 失败证据（逐字出自 results/*.json）

| 轮次 | 文件 | 时间戳 | 步数 | 成功率 | 坠毁率 | mean_err(kt) |
|---|---|---|---|---|---|---|
| v1 baseline | `results/jsbsim_ppo_forward_baseline_results.json` | 2026-08-28 16:15:45 | 600k | 0% | 0% | 33.65 |
| v2（repair override 后） | `results/jsbsim_ppo_forward_results.json` | 2026-08-28 18:25:29 | 500k | 0% | 0% | 28.37 |

两轮共性：**0% 成功 + 0% 坠毁**。策略既不前飞也不失控——v2 末段 10% 平均速度误差 28.37 kt，即策略全程停在 ~1.6 kt（≈悬停），是《训练方法与坠机诊断报告.md》§5 记录的"趴地"死锁在 JSBSim 前飞通道的再现（同构：**目标方向无每步正收入，动作风险为负，不动即局部最优**）。区别仅在：旧环境的"趴地"是趴在地面，forward 任务 reset 即 20 m 悬停（`_fly_to_hover` 建立），所以趴的是"悬停锁死"。

### 1.2 v2 reward 为什么给不出前进梯度（4 个结构性原因）

v2 奖励（jsbsim_tasks.py L359-364）：
```
r = 10*(|prev_u-30| - |u-30|)      # 速度势函数（每靠近 1 kt +10）
  + 5*(|prev_alt-20| - |alt-20|)   # 高度势函数
  + (2.0 if 带内 else -0.05)        # 带内 AND 门：|u_err|<5kt 且 |alt_err|<3m
  - 0.05*|roll| - 0.01*Σa² - (0.2 蹲地)
  - 50 坠毁
```

1. **速度项只有"增量"没有"存量"**：势函数是 one-shot 梯度，加速全程 0→30 kt 的总势差 300 被摊进整条轨迹，且在未动时恒为 0。悬停在原地的每步收入 ≈ 0（只有 -0.05 带外惩罚），而低头试探立刻招致高度势函数扣分与坠毁风险（-50）。早期期望收益：不动 ≈ -100/回合，试探 ≈ 大方差（-50 坠毁 ~ 少量势差）→ PPO 收敛到"不动"。§5 结论逐字适用："奖励结构没有给'起飞'（此处为'前飞'）这个动作提供任何梯度"。
2. **带内奖励是 AND 门且初始不可达**：`in_bounds = speed_err<5 且 alt_err<3`，从 0 kt 出发必须先穿过 0→25 kt 的整个加速区才能首次点亮 +2；加速瞬态必然掉高度（升力前倾），AND 门在瞬态恒为假 → 加速过程拿不到任何带内收入，反而吃高度势函数罚。
3. **低头通道风险不对称**：纵向通道开环强不稳定（冒烟实测 ele=+0.10 恒定 5s 俯仰 -60.4° 穿地，mailbox-A 18:50），v2 的 -50 坠毁罚 + 无低头正收益，使 u_pitch>0 的探索方差极大而收益为 0 → 策略学会永远 u_pitch≈0。
4. **拖延无成本**：v2 只有 -0.05/步带外惩罚，悬停 20s 总代价 ~ -50~-100，与试探一次坠毁 -50 同量级——"苟着"不比"试错"差。§5 成功配方（v2 简化环境）中的"起飞拖延惩罚"在 forward v2 里缺失。

### 1.3 roll_v2 方法论对照（本设计的方法来源）

roll_v2（`results/jsbsim_ppo_roll_results.json`，18:17:43，5 种子×20 回合 100%/0%/1.97°）相对 baseline 的改法，映射到 forward：

| roll_v2 做法 | forward v3 对应 |
|---|---|
| 速率塑形：奖励朝目标方向的滚转速率（解决"持续压杆"探索难题） | 低头姿态塑形：未达目标空速时按低头幅度给每步正收益（低头是前飞的物理先导） |
| 带内 +2 与带外 -0.05 的宽窄门设计 | 速度带/高度带**拆开**给分（AND 门改 OR 门），加速瞬态的partial progress 有收入 |
| 高度仅小权重绝对惩罚 -0.05*alt_err（不与机动梯度打架） | 高度势函数降权 5.0→2.0 + 小绝对惩罚 0.02*alt_err |
| 环境 reset 即建立悬停起点（课程初始化思想保留） | 不变：`_fly_to_hover` 起始 |
| §5 势函数塑形"每靠近目标 1 m 立即 +1" | 速度"生计奖励"：每步按当前空速给正收入（存量，非增量） |

## 2. v3 reward 数学形式（全部改动限于 reward 块与类常量）

记 `u = s['u']`（体轴前向速度 m/s）、`U* = target_speed_kts / MPS2KTS = 15.43 m/s`、
`U_ov = (target+5 kt)/MPS2KTS = 18.0 m/s`、`θ = s['pitch']`、`θ_max = PITCH_CMD_MAX = 8°`、
`e_u = |u_kts - 30|`、`e_h = |agl - 20|`、`prev` 为上一步状态：

```
r = 10.0 * (|prev_u_kts - 30| - e_u)                 # (A) 速度势函数 [保留 v2]
  + 2.0 * (|prev_agl - 20| - e_h)                    # (B) 高度势函数 [v2 的 5.0 → 2.0]
  + 1.5 * clip(u / U*, 0, 1)                         # (C) 速度生计奖励 [新增]
  - 0.15                                             # (D) 拖延成本 [新增]
  + 0.5 * min(1, max(0,-θ)/θ_max)   (仅 u < U*)      # (E) 低头姿态塑形 [新增]
  + 1.2 * (e_u < 5 kt)                               # (F) 速度带 [新增, 替换 v2 AND 门]
  + 0.8 * (e_h < 3 m)                                # (G) 高度带 [新增, 同上]
  - 0.05 * |roll|                                    # (H) 滚转惩罚 [保留 v2]
  - 0.02 * e_h                                       # (I) 高度绝对惩罚 [新增]
  - 0.3 * max(0, u - U_ov)                           # (J) 超速护栏 [新增]
  - 5.0 * max(0, -θ - θ_max)                         # (K) 俯冲护栏 [新增]
  - 0.5 * (agl<1.0 且 steps>50)                      # (L) 蹲地成本 [v2 的 0.2 → 0.5]
  - 0.01 * Σa²                                       # (M) 动作能量 [保留 v2]
  - 50   (坠毁)                                      # (N) [保留 v2]
```

不动的东西（明确边界）：
- 4 维动作契约、观测 12 维、`_apply_forward` 执行包络、`_fly_to_hover` 起始、`_check_crash`、
  episode 长度、**success 判定口径**（`in_bounds_steps > 200`，即速度带内累计 >4 s）全部不变；
- 其他任务通道（hover/landing/roll/yaw/waypoint）零改动。

### 每项意图

| 项 | 意图 | 反 v2 病灶 |
|---|---|---|
| A 速度势函数 | 保留因果梯度：每靠近 1 kt 立即 +10 | 病灶 1 的增量部分保留 |
| B 高度势函数降权 | 高度仍是目标但不再淹没前进梯度（瞬态下沉 0.01m/步只罚 ~0.02） | 病灶 2 |
| C 速度生计奖励 | **核心解药**：低头→加速的第一步立即有每步正收入（存量收入），悬停收入归 0 | 病灶 1 |
| D 拖延成本 | 悬停 20s 稳定 -170/回合，"苟着"严格劣于任何尝试（§5 拖延惩罚移植） | 病灶 4 |
| E 低头塑形 | 给出"该往哪推杆"的方向先验（对齐 roll_v2 速率塑形思想）；u≥U* 后关闭防"带速低头" | 病灶 3 |
| F/G 拆带 | 加速途中先拿速度带 +1.2，高度回带再拿 +0.8，partial progress 即时兑现 | 病灶 2 |
| J 超速护栏 | 收入在 U* 饱和、超过 35 kt 转罚，防冲速度发散 | 新增鲁棒性 |
| K 俯冲护栏 | 低头超过 ±8° 指令包络后每弧度罚 5.0（净值为负），配合内环仰角限制防栽头换速度 | 病灶 3 对偶风险 |
| L 蹲地加重 | 本任务坠毁只判姿态角，"栽到地上赖着"不能成为吸引子 | 边界情形 |
| I 高度绝对项 | 打破"下沉后赖着不动"的中性平衡（势函数对静止不动恒为 0） | 边界情形 |

### 关键量级账（每步，50 Hz）

- 悬停不动：`0 + 0 + 0 - 0.15 - 0.02·e_h ≈ -0.17/步` → 20 s ≈ **-170/回合**（v2 ≈ -100）
- 低头 8° 加速段（u≈5 m/s）：`(A)+0.5 + (C)+0.5 + (E)+0.5 + (B)≈-0.02 - 0.15 ≈ +1.3/步` → 试错方向全程为正
- 带内巡航（30 kt @ 20 m）：`(C)+1.5 + (F)+1.2 + (G)+0.8 - 0.15 ≈ +3.35/步`
- 带内 200 步 → success（口径不变），一回合带内收入 ~ +670 >> 悬停 -170

### 预期行为曲线（写于训练前，供事后对照）

- 0~100k：ep_rew 从 ≈-170 抬升，info.u_kts 出现非零峰值（策略开始低头试探）；
- 100k~300k：u_kts 均值爬向 10~25 kt，坠落/拉起反复，带内步数开始累积；
- 300k~500k：u_kts 稳定在 25~35 kt、高度回 17~23 m，in_bounds_steps 越过 200 → success 出现并抬升；
- 失败形态（若出现）：u_kts 峰值 <5 kt 不再增长（仍是趴地 → 本设计判 FAIL，回到诊断，不盲目加步数）；或 u_kts 冲 >40 kt 且高度塌（护栏权重问题 → 调 J/K，不视为新一轮改写前的草率判断）。
