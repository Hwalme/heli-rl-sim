## 三、坠机根本原因深度分析

### 3.1 坠机案例详细解剖 (takeoff_fg, seed=0, ep=1)

#### 3.1.1 初始阶段 (step 0-29)

```
step=0  agl=0.000m  roll=0.0°   pitch=0.0°   vz=0.18  coll=0
step=10 agl=0.058m  roll=-0.4°  pitch=-0.5°  vz=0.25  coll=0
step=20 agl=0.099m  roll=-0.5°  pitch=-1.6°  vz=0.16  coll=0
step=29 agl=0.122m  roll=-0.5°  pitch=-2.5°  vz=0.10  coll=0
```

**关键发现**:
- **总距 coll=0**: 模型输出的总距指令为 0，导致升力不足
- **爬升极慢**: 29步仅爬升 0.122m，爬升率从 0.18 降到 0.10 m/s
- **姿态缓慢恶化**: roll 从 0° → -0.5°，pitch 从 0° → -2.5°

#### 3.1.2 坠机前 (step 482-491)

```
step=482 agl=0.334m  roll=-55.0°  pitch=11.0°  vz=-0.69  coll=0
step=486 agl=0.272m  roll=-57.2°  pitch=9.9°   vz=-0.86  coll=0
step=491 agl=0.175m  roll=-60.2°  pitch=8.0°   vz=-1.10  coll=0
```

**关键发现**:
- **总距始终为 0**: 整个 492 步中 coll=0，模型完全没有增加总距
- **滚转失控**: roll 从 -55° 恶化到 -60.2°，超过 60° 坠毁阈值
- **高度下降**: agl 从 0.334m 降到 0.175m，直升机在下降
- **坠毁判定**: roll > 60° 触发坠毁条件

### 3.2 坠机根本原因链

```
奖励函数设计问题
    ↓
地面阶段姿态惩罚过重 (x1.5)
    ↓
模型学会"保持总距=0"来避免姿态变化 (因为不爬升就不会有姿态扰动)
    ↓
升力不足，直升机一直在地面附近 (agl<0.5m)
    ↓
地面效应 + 风干扰导致滚转角缓慢累积
    ↓
滚转角达到 60° 触发坠毁
```

### 3.3 其他任务坠机原因分析

#### 3.3.1 航点任务 (waypoint) - 60% 坠毁率

- **原因**: 任务复杂度最高，需要同时控制位置、速度、姿态
- **表现**: 0% 成功率，60% 坠毁率
- **改进方向**: 需要课程学习（先悬停→前飞→简单航点→复杂航点），或增加训练步数

#### 3.3.2 偏航任务 (yaw) - 0% 坠毁率但 37% 成功率

- **原因**: 偏航控制困难，抗扭矩补偿不足
- **表现**: 不坠毁但无法达到目标航向
- **改进方向**: 调整偏航控制增益，增加抗扭矩补偿

### 3.4 历史坠机问题总结

从整个训练过程来看，坠机问题经历了以下阶段：

1. **初期 (JSBSim 环境搭建)**: 物理模型参数错误导致频繁坠机，通过修复 REPAIR_OVERRIDES 解决
2. **中期 (直接控制训练)**: 悬停/前飞等任务基本无坠毁，起飞任务成功率低但不坠毁
3. **近期 (增强版训练)**: takeoff_hard 达到 100% 成功率、0% 坠毁率
4. **当前 (FG对齐版)**: 控制架构变化导致重新学习，地面阶段 3% 坠毁率

**核心结论**: 坠机主要发生在**地面阶段**和**控制架构切换期**，通过奖励函数调优和课程学习可以有效解决。

## 五、模型架构与控制策略分析

### 5.1 两种控制架构对比

#### 5.1.1 直接控制架构 (takeoff, takeoff_hard)

```
RL策略 (4维输出)
    ↓
[总距, 俯仰, 横滚, 脚蹬] 直接映射到舵面
    ↓
JSBSim 飞行动力学
```

**优点**:
- 控制直接，响应快
- 策略空间简单，容易学习
- 训练效率高，100万步即可收敛

**缺点**:
- 与 FlightGear 实际控制架构不匹配
- 舵面直接控制需要精确的物理模型
- sim-to-real gap 较大

#### 5.1.2 姿态指令控制架构 (takeoff_fg, 对齐 FG)

```
RL策略 (4维输出)
    ↓
[总距指令, pitch目标, roll目标, yaw目标] (外环 5Hz)
    ↓
内环 PID 姿态稳定控制器 (每步运行)
    ↓
[总距, 升降舵, 副翼, 方向舵] 舵面控制
    ↓
JSBSim 飞行动力学
```

**优点**:
- 与 FlightGear 实际控制架构一致
- 内环 PID 提供基础稳定性，降低 RL 学习难度
- sim-to-real gap 小

**缺点**:
- 策略空间不同，需要重新学习
- 外环 5Hz 控制频率低，响应慢
- 内环 PID 参数需要精心调优
- 训练时间长（300万步）

## 七、奖励函数设计分析

### 7.1 起飞任务奖励函数组成

| 奖励项 | 权重 | 作用 | 潜在问题 |
|--------|------|------|----------|
| **高度生计奖励** | 0.5 | 鼓励爬升 | 可能导致为了高度忽视姿态 |
| **姿态惩罚** | 0.5 (地面x1.5) | 抑制姿态振荡 | 地面过重可能导致不敢爬升 |
| **稳定爬升率奖励** | 0.2 | 鼓励 1-3 m/s 稳定爬升 | 范围可能不合适 |
| **存活奖励** | 0.01 (地面x1.5) | 鼓励存活 | 权重太小 |
| **总距平滑惩罚** | 0.3 | 抑制总距剧烈变化 | 可能限制正常起飞 |
| **姿态稳定奖励** | 0.1 (地面x1.5) | 鼓励小姿态 | FG版新增 |
| **成功奖励** | 20.0 | 大奖励激励成功 | 稀疏奖励 |
| **坠毁惩罚** | -5.0 | 惩罚坠毁 | 可能不够大 |

### 7.2 奖励函数设计问题

#### 问题1: 地面阶段姿态惩罚过重

**现象**: FG版坠机案例中 coll=0，模型为了避免姿态惩罚而保持总距为0

**原因**: 地面阶段姿态惩罚 x1.5，而高度奖励只有在爬升时才能获得。模型发现"不爬升=无姿态变化=无惩罚"是最优策略。

**改进建议**:
- 降低地面阶段姿态惩罚权重（从 x1.5 降到 x1.2）
- 增加地面阶段爬升奖励（即使高度低也给予爬升激励）
- 增加总距为0的惩罚（鼓励模型尝试起飞）

#### 问题2: 成功奖励稀疏

**现象**: 成功奖励只有在达到目标高度并稳定2秒后才给予，训练初期很难获得

**原因**: 稀疏奖励导致探索效率低，模型需要随机探索到成功状态才能学习

**改进建议**:
- 增加中间奖励（如每达到一定高度给予小奖励）
- 使用奖励整形（reward shaping）
- 课程学习（先降低目标高度，逐步增加）

#### 问题3: 坠毁惩罚不够大

**现象**: 航点任务 60% 坠毁率，说明模型没有充分避免坠毁

**原因**: 坠毁惩罚 -5.0 相对于存活奖励（每步 0.01）来说不够大

**改进建议**:
- 增加坠毁惩罚（从 -5.0 降到 -20.0）
- 增加坠毁前的姿态惩罚（提前抑制危险姿态）

## 八、操作层面分析

### 8.1 控制输入分析

#### 8.1.1 直接控制模式 (takeoff_hard)

成功案例的控制输入特征:
- **总距**: 从 0.5 快速增加到 0.7，然后稳定在 0.6-0.7
- **俯仰**: 小幅度调整（±0.3），保持小俯仰角
- **横滚**: 小幅度调整（±0.3），对抗风干扰
- **脚蹬**: 抗扭矩补偿，随总距变化

#### 8.1.2 姿态指令模式 (takeoff_fg)

成功案例的控制输入特征:
- **总距指令**: 从 0.5 增加到 0.65，然后稳定
- **pitch目标**: 保持在 0° 附近（±5°）
- **roll目标**: 保持在 0° 附近（±5°），对抗风干扰
- **yaw目标**: 保持航向稳定

### 8.2 执行器特性影响

| 执行器特性 | 对起飞的影响 | 应对策略 |
|------------|--------------|----------|
| **总距速率限制** | 起飞响应变慢，需要提前增加总距 | 模型学会提前增加总距 |
| **姿态目标速率限制** | 姿态响应受限，不能快速纠正大偏差 | 模型学会保持小姿态偏差 |
| **执行器延迟** | 控制滞后，容易振荡 | 内环 PID 提供阻尼 |

### 8.3 传感器特性影响

| 传感器特性 | 对起飞的影响 | 应对策略 |
|------------|--------------|----------|
| **高度计噪声** | 高度判断不准确，可能误判起飞状态 | 模型学会使用速度信息辅助判断 |
| **姿态角噪声** | 姿态反馈有误差，控制精度降低 | 内环 PID 滤波 |
| **角速度噪声** | 阻尼控制受影响，可能振荡 | 降低角速度反馈增益 |
| **传感器延迟** | 控制滞后，容易振荡 | 内环 PID 提供预测性控制 |

## 九、Sim-to-Real Gap 分析

### 9.1 JSBSim 与 FlightGear 差异

| 维度 | JSBSim (RL训练) | FlightGear (实际演示) | 差异影响 |
|------|------------------|------------------------|----------|
| **飞行动力学** | JSBSim 1.3.1 | JSBSim (FG内置) | 基本一致 |
| **飞行器模型** | ah1s (AH-1S) | bo105 (Bo-105) | **较大差异** - 不同直升机 |
| **控制架构** | 直接控制 / 姿态指令 | 外环5Hz + 内环56Hz | FG版已对齐 |
| **大气模型** | 简化风 + Dryden紊流 | 更真实的大气模型 | 中等差异 |
| **地面效应** | JSBSim 内置 | 更真实的地面效应 | 中等差异 |
| **传感器模型** | 简化噪声+延迟 | 更真实的传感器特性 | 中等差异 |
| **执行器模型** | 简化速率限制+延迟 | 更真实的舵机动态 | 中等差异 |
| **网络延迟** | 无 | telnet 通信延迟 | FG版已模拟 |

### 9.2 核心差异: 飞行器模型不同

**最大的 sim-to-real gap 来源**: RL 训练使用 AH-1S 武装直升机，而 FlightGear 演示使用 Bo-105 轻型直升机。

两者差异:
- **重量**: AH-1S 约 4500kg，Bo-105 约 2500kg
- **旋翼**: AH-1S 两叶旋翼，Bo-105 四叶旋翼
- **动力**: AH-1S 双发涡轴，Bo-105 双发涡轴
- **操纵特性**: 完全不同的操纵响应和配平特性

**改进建议**:
1. 在 FlightGear 中使用 AH-1S 模型进行演示（如果有）
2. 或者在 RL 训练中使用 Bo-105 模型（需要搭建 JSBSim 模型）
3. 或者使用域随机化（Domain Randomization）让模型适应不同飞行器特性

### 9.3 减小 Sim-to-Real Gap 的措施

已实施:
1. ✅ 强风+阵风+紊流+风切变模拟
2. ✅ 传感器噪声+延迟模拟
3. ✅ 执行器速率限制+延迟模拟
4. ✅ 初始姿态随机化
5. ✅ FG 控制架构对齐（外环5Hz姿态指令+内环PID）

待实施:
1. ⏳ 飞行器模型对齐（AH-1S vs Bo-105）
2. ⏳ 更真实的地面效应模拟
3. ⏳ 发动机动态模拟（转速、功率、温度）
4. ⏳ 系统延迟模拟（计算延迟、通信延迟）
5. ⏳ 域随机化（质量、惯性、气动参数随机化）

## 十一、结论

### 11.1 核心成果

1. **基础任务全面达标**: 悬停、着陆、滚转、增强版起飞均达到 100% 成功率、0% 坠毁率
2. **起飞任务三版本迭代**: 从基础版 11% → 增强版 100% → FG对齐版 90%，难度递增
3. **Sim-to-Real Gap 大幅减小**: 通过环境随机化、传感器/执行器模拟、控制架构对齐，FG对齐版在高难度环境下达到 90% 成功率
4. **坠机根本原因查明**: 主要发生在地面阶段，由奖励函数设计问题导致模型保持总距为0

### 11.2 核心问题

1. **FG对齐版坠毁率 3%**: 未达到 0% 坠毁率的严格验收标准，需要调整奖励函数
2. **偏航任务成功率 37%**: 抗扭矩补偿不足，需要调整控制增益
3. **航点任务成功率 0%**: 任务复杂度最高，需要课程学习和更多训练
4. **飞行器模型不匹配**: AH-1S (训练) vs Bo-105 (演示)，是最大的 sim-to-real gap 来源

### 11.3 关键建议

1. **优先调整奖励函数**: 降低地面阶段姿态惩罚，增加爬升奖励和坠毁惩罚，预计可将坠毁率从 3% 降到 0%
2. **增加训练步数**: takeoff_fg 从 300万步增加到 500万步，预计可将成功率从 90% 提升到 95%+
3. **飞行器模型对齐**: 长期来看，需要统一训练和演示使用的飞行器模型
4. **域随机化**: 增加物理参数随机化，提高模型鲁棒性和泛化能力
