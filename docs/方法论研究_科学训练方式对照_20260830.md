# 方法论研究：科学训练方式与开源资源对照（2026-08-30）

> **作者**：轨道 E（方法论研究支持职责）。**用途**：对照本项目当前的奖励/课程/评估做法与开源社区及文献中的科学做法，给出按 ROI 排序的可落地建议。**对象读者**：A 轨（直接执行方）与用户。

## 0. 一个重要发现：我们的问题在文献里全有名字

| 本项目踩的坑 | 文献/社区术语 | 出处 |
|---|---|---|
| 滑翔起飞与垂直起飞奖励等价、策略钻空子 | **Reward Hacking / Specification Gaming** | Lilian Weng 综述 |
| 每加一条成功判据就手工镜像进奖励（v5→v5.2.2 已三轮） | 这正是**约束式 RL（Safe RL）**形式化解决的问题 | OmniSafe / Safety-Gymnasium |
| 进度奖励塑形是拍脑袋写的 | **势函数奖励塑形（PBRS, Ng 1999）**——有最优策略不变性保证 | Stanford (ICML'99) |
| waypoint 卡 48.4%、课程靠固定回合数升阶 | **自动课程学习（ACL）** | IJCAI'20 综述 |
| 训练先验难找、冷启动慢 | **示范热启动/学徒学习**——Stanford 自主直升机整个系列就是这个范式 | Abbeel/Coates/Ng |
| AH-1S 仿真里起飞翻覆、稳不住 | **JSBSim 官方讨论区 #1148 有人讨论同一机型的同一问题** | GitHub Discussions |

结论：**我们不是在做没人做过的事，我们是在无意识地重新发明文献里已经标准化的东西，而且有几处发明得不如标准版好。**

## 1. 按落地成本×收益排序的六项建议

### R1（零成本，立即做）：把"奖励审计"升级为标准化的 reward-hacking 检测
我们自制的 `audit_rewards.py`（构造 V/G 轨迹对照）在方法论上正是文献里的 specification testing 思路，方向正确。补两件事：
- 每次训练**自动**记录每步奖励分布（各分项直方图），训练前后对比——分布漂移即 hack 预警（rewardspy 库的思路）；
- 把 G1 审计挂进训练脚本作为提交前检查，而不是靠人记得跑。

### R2（低成本低风险）：势函数化（PBRS）塑形
现状：奖励里 progress 项、惩罚项、门槛镜像项混在一起，没有理论边界，每轮调参都是玄学。
做法：把"靠近目标的每步进步"类奖励改写成严格势函数形式 F(s,s')=γΦ(s')−Φ(s)（如 Φ=−α·|alt_err|−β·|drift|−γ·|heading_dev|），**用 Gymnasium RewardWrapper 实现、与任务奖励分离**。理论保证：不改变最优策略（函数近似下会衰减，但方向正确）。好处：以后加新判据（如航向）只需改势函数 Φ 一处，不用再手工镜像三轮。
出处：Ng, Harada & Russell 1999（[论文](http://robotics.stanford.edu/~ang/papers/shaping-icml99.ps)）、[Gymnasium wrapper 体系](https://gymnasium.farama.org/)、[Weng 综述](https://lilianweng.github.io/posts/2024-11-28-reward-hacking/)。

### R3（中等成本，强烈推荐）：约束式 RL——把"门槛"从奖励里拿出来
现状痛点：坠毁惩罚、漂移<30m、航向<15°、近地慢降——每条都是"判据 + 手工调权重的惩罚镜像"，v5 到 v5.2.2 三轮就是在人肉解这个多目标权衡。
科学做法：**cost 约束**——奖励只留任务目标（到达+保持），四条门槛全部变成 cost 信号 c_i(s)，用 **PPO-Lagrangian**（约束违反自动调拉格朗日乘子）保证 cost≤阈值。判据改了只改阈值，不动奖励。
落地：[OmniSafe](https://github.com/PKU-Alignment/omnisafe)（北大对齐团队，PPO-Lag/CPO 即插用）+ [Safety-Gymnasium](https://github.com/PKU-Alignment/safety-gymnasium)（cost 信号协议参考）；我们的 env 只需在 info 里多吐 4 个 cost 字段。
**建议**：landing v5.2.2 若再不达标，A 轨下一个迭代直接切 PPO-Lag，不要继续人肉调权重。

### R4（对症下药）：示范热启动——Stanford 直升机的标准范式
Abbeel/Coates/Ng 的自主直升机系列（[ICML'03](https://link.springer.com/rwe/10.1007/978-1-4899-7502-7_16-1)、[NeurIPS'06](https://papers.neurips.cc/paper_files/paper/2006/file/98c39996bf1543e974747a2549b3107c-Paper.pdf)、[IJRR'10](http://ai.stanford.edu/~acoates/papers/AbbeelCoatesNg_IJRR2010.pdf)）路线 = 人类示范 → 学奖励/模仿 → RL 精调 → 实机。我们手里已有两样现成资产：
- 验证过的启发式控制器（`alt_coll_cmd`）和悬停策略 → **行为克隆热启动**（一天工作量）解决冷启动慢；
- 验收线"1000 小时操纵数据"以后就是真人示范库 → **逆强化学习/学徒学习**的直接对口，两条线在方法论上会合（这值得写进验收方案的先进性论证）。
开源参考：[abbeel-heli-rl](https://github.com/srirambandi/abbeel-heli-rl)、[heli-gym](https://github.com/ugurcanozalp/heli-gym)。

### R5（低成本）：课程自动化——别再用固定回合数升阶
waypoint 48.4% 卡线的直接原因之一是"每 500 回合升阶"与实际学习速度脱钩。文献标准做法是**按能力自动调课程**：任务通过率 ≥85% 才升阶、掉下 70% 就降阶（success-rate-triggered curriculum，约 20 行代码）；进阶版参考 [C-Planning](https://arxiv.org/abs/2110.12080) 与 [awesome-gcrl](https://github.com/GongXudong/awesome-gcrl)。

### R6（已在做，保持）：级联控制架构 + 固定种子评估
SAS 内环 + RL 外环是文献标准架构（Stanford/ETH 冠军系统同款），不要被"端到端"诱惑推倒；固定随机种子的确定性评估就是我们隐性在做的 PEGASUS 式 policy search（[出处](https://link.springer.com/rwe/10.1007/978-1-4899-7502-7_16-1)）。

# v2 增补（2026-08-30 深挖）：上游引擎缺陷实锤与机型战略

## 4. 根因上溯：我们的偏航自旋是 JSBSim 官方承认的引擎级 bug 的症状

- **[JSBSim #1139《Helicopters cannot be trimmed in flight》](https://github.com/JSBSim-Team/jsbsim/issues/1139)**（2024-08，**维护者 bcoconni 亲自提交，bug+feature 双标，至今 OPEN**）：配平算法假定升力来自机翼、靠迎角保高度，**对旋翼升力完全不适用——JSBSim 直升机在飞行中不存在有效配平解**。我们实测的 30~84°/s 残余自旋、起飞翻覆，全部是该缺陷的症状。
- **[#1148](https://github.com/JSBSim-Team/jsbsim/discussions/1148)**：有人用 AH-1S 自带 AFCS 指令在 Unreal 里稳定起飞成功，但一松舵就左右失控——与我们同病。
- 帖内情报：FG 生态里**真正的 JSBSim 直升机只有 Alouette-III 和 R22**（其余多为 YASim）。

## 5. 本地考证（动手验证，非纸上谈兵）

1. **AH-1S 自带 AFCS 配平架构**：`Systems/trim_control.xml` + `Systems/steady_flight_data.xml`——含自动配平表（含 `ap/afcs/automatic/antitorque-trim-ctrl-rad` 反扭矩配平）与手动通道（`fcs/manual/yaw-trim-cmd-norm` 等），总开关 `fcs/automatic/steady-flight-data-enable` **默认关闭**。
2. **实测探针（15s 悬停 collective=0.70）**：
   - 现状（无配平）：峰值自旋 83.7°/s，15s 航向漂移 -114.9°；
   - 开 SFD 自动配平表：**数值爆炸（r→10^158, NaN）**——配平表在爬升工况发散，作者默认关它是诚实的；
   - 手动偏航配平通道：±0.02/-0.05 **同样爆炸**，+0.05/+0.10 掉高且航向更糟——**该通道本身不可用**（怀疑与我们的 fcs/adj 增益 override 相互作用，但可变组合全试过均不佳）。
3. **模型自我声明**：AH-1S 头部注释 "ALPHA release... may not even properly fly as expected... development purposes ONLY"（作者 Thomas Kreitler，2010）。
4. 本地 pip 版 JSBSim 仅带这一架直升机；R22/Alouette-III 在 [FGData 仓库](https://github.com/FlightGear/fgdata)。

## 6. 战略结论与行动

**停止对 ALPHA 模型的外科手术。** RL 在压自旋上的每一分能力都建立在流沙上（配平通道实测不可用）。
- **B 轨（决策项）**：从 FGData 移植 R22 或 Alouette-III 的 JSBSim FDM，跑同款自旋探针，产出《机型替代对比报告》（R22 灵活/Alouette 更重更接近 AH-1S 量级）；保留 AH-1S 数据作对照与上游贡献素材。
- **上游贡献**：把我们的量化证据（自旋数据、SFD/手动配平爆炸复现步骤）回帖 #1139/#1148——对社区真有用，也为项目背书。
- **A 轨**：v5.2.2 作为当前代继续；若机型切换获批，悬停配平需重新标定后重训（属于新代际）。
- **生态包参考**：[gymnasium-jsbsim](https://getsafety.com/packages/pypi/gymnasium-jsbsim)、[Gym-JSBSim](https://github.com/Gor-Ren/gym-jsbsim)、[jsbgym](https://pypi.org/project/jsbgym/)、[Tunnel 空战训练环境（arXiv 2505.01953）](https://arxiv.org/html/2505.01953v1)、[AeroEd JSBSim+SB3 教程](https://www.aeroed.ai/projects/jsbsim-autopilot-rl/)。

## 7. 机型移植试验实录（2026-08-30 下午，主 E 亲自执行）

**试验目的**：验证"换机型治自旋"路线的可行性。**结论：技术上可行但不是快速胜利，转为 B 轨有界任务。**

| 项 | 结果 |
|---|---|
| R22（FGMEMBERS 仓库） | **YASim FDM，非 JSBSim，不可用**（#1139 帖内情报有误或指旧版） |
| Alouette-III（FGMEMBERS 仓库） | 确为 JSBSim（Artouste IIIB 涡轴+主/尾旋翼引擎文件齐全），但 FG 打包带 3 处缺陷 |
| 已修缺陷 | ① `landing-gear.xml` switch 默认值写成属性路径（语法错误）；② 依赖纯 JSBSim 不存在的 `/environment/snow-level-m`；③ 依赖 `/environment/metar/snow-norm` |
| 未竟摩擦 | FG→纯 JSBSim 的属性桥接（/controls 预种子、/environment 树、load 期求值顺序），`set_property_value` 对新属性静默无效必须走 XML 声明 |
| 迁移工作量估计 | **1~2 个专人日**（非一下午）：补齐 FG 属性桥 + 清点剩余缺陷 + 悬停配平标定 + reset 文件 |
| 台架资产 | `_fdmroot/`（半移植台架，含 E0PROPS 注入器与迭代补属性脚本）+ `_fdm_src/`（两个机型源），已 gitignore，B 轨接力 |

**近期决策（E 终裁）**：当前代继续用 AH-1S（靠 REPAIR_OVERRIDES 飞行 + RL 外环补偿自旋，用户可感知的"垂直起降"由 v5.2 判据+G4 闸门保证）；机型替代由 B 轨按本节资产 bounded 推进，产出对比报告后 E 终裁是否切换。**R22/Alouette 的教训同时写进验收方案风险节：公开 JSBSim 直升机生态极其薄弱，自研 FDM 或引擎层修配平（给上游 #1139 提 PR）是中期选项。**
