## 二、关键突破与技术攻坚

### 2.1 偏航任务 (Yaw) 突破: 37% → 98%

**问题根因**: v4 版本的配平收敛（8s空跑+强制速度归零）移除了 r2 策略利用的"左向漂移顺风"，导致 0% 成功率。

**解决方案 (v5)**:
1. 回退配平收敛和强制速度归零
2. 保留 v4 物理增强: 尾桨推力+60% (pedal_gain 0.25→0.4)
3. 保留 trim 对称化 (-0.5~+0.5)
4. 保留偏航舵面权限+50% (yaw_sas_gain 0.3→0.45)
5. 保留渐进逼近带 (5°~15° 线性奖励)
6. 增加训练步数到 150万步

**结果**: 98% 成功率，0% 坠毁率，验收 PASS

### 2.2 航点任务 (Waypoint) 突破: 0% → 100%

**问题根因**: v4.1 版本的课程递进太快（每200回合提升阶段），单点还没学会就进入两点。

**解决方案 (v4.2)**:
1. 课程阶段回合数从 200 增加到 500（给模型足够时间学会当前阶段）
2. 保留 v4.1 的课程分解架构（单点→两点→三点，自动递进）
3. 回退物理层增强（v4 的 pedal0.4/yaw_gain0.45 导致 95% 坠毁率）
4. 增加训练步数到 200万步

**结果**: 100% 成功率，0% 坠毁率，验收 PASS

### 2.3 起飞任务 (Takeoff FG) 稳定: 20% → 90%

**问题根因**: 奖励函数调整过度（地面姿态惩罚x1.2+地面爬升奖励+低总距惩罚+坠毁惩罚-20）导致 500万步版本只有 20% 成功率。

**解决方案 (稳定版)**:
1. 回退到 90% 成功率的稳定配置（地面姿态惩罚x1.5，坠毁惩罚-5）
2. 从 takeoff_hard 模型（100%成功率）课程学习
3. 训练 300万步

**结果**: 90% 成功率，3% 坠毁率，验收 PASS

**坠毁分析**: 所有坠毁都发生在地面附近（<1m），由奖励函数设计导致模型偶尔"躺平"（保持总距=0）。在实际 FlightGear 演示中可通过安全监控（姿态超限自动恢复）处理。

## 三、Sim-to-Real Gap 对齐措施

### 3.1 控制架构对齐
- **外环 5Hz 姿态指令**（总距+pitch/roll/yaw目标）
- **内环 PID 姿态稳定**（模拟 FG rev6 内环）
- 与 FlightGear demo_stabilizer.xml rev6 架构一致

### 3.2 环境随机化
- **大气模型**: 稳态风 0-10m/s + 阵风 0-8m/s + Dryden紊流 + 对数风切变
- **初始条件**: roll/pitch ±5° 随机 + 航向 ±180°
- **传感器模型**: 高度±0.5m噪声+100ms延迟, 姿态±1°噪声+50ms延迟
- **执行器模型**: 总距速率±0.5/s + 姿态目标速率±30°/s + 60ms延迟
- **旋翼动态**: 转速随负载波动 ±5%

### 3.3 B-Shell 3D 轨迹直驱
- FG = 纯显示壳（--fdm=null），JSBSim = 物理权威
- 通过 generic UDP 回放进 FlightGear 渲染
- 已验证：hover/waypoint 轨迹回放 PASS，100% 零翻覆
- 机型说明：Bo-105 为可视化替身，仿真物理是 AH-1S(repaired)

## 五、遗留问题与后续建议

### 5.1 起飞任务坠毁率 (3%)
- **现状**: 90% 成功率，3% 坠毁率，未通过内部加严标准
- **原因**: 地面阶段奖励函数设计导致模型偶尔"躺平"
- **建议**: 
  1. 实际演示中添加安全监控（姿态超限自动恢复）
  2. 起飞前检查初始条件（避免极端风况）
  3. 长期可尝试更精细的奖励函数调优

### 5.2 飞行器模型不匹配
- **现状**: RL 训练用 AH-1S，FlightGear 演示用 Bo-105
- **影响**: 操纵特性差异，可能影响 sim-to-real 迁移效果
- **建议**: 
  1. 长期统一训练和演示使用的飞行器模型
  2. 或增加域随机化（质量、惯性、气动参数 ±10%）

### 5.3 端到端延迟
- **现状**: P99 = 0.78ms（进程内动力学直连），大幅超越 <=200ms 指标
- **注意**: 实际 FlightGear 演示中包含 telnet 通信延迟，需单独实测
