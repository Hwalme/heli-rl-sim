# 大规模训练与数据生产路线图（Antigravity 执行版，2026-09-02）

> **制定**：轨道 E。**执行**：Antigravity 并行会话组（用户指派 AG-1/AG-2/AG-3）。
> **前提**：一代（AH-1S）已闭环 6/6 PASS 96.5%；二代（helispike）适配器就绪（rl_train/helispike_env.py，契约 v1.1）。
> **目标**：二代全科目训练链 + 操纵数据时长积累 + 评测矩阵，产出全部可溯源证据。

## 0. 全局纪律（每个 Antigravity 会话入职第一条）

1. 必读：`事故复盘与整改令_20260830.md`（六铁律+五道闸）、`决策台账.md`、本文件。
2. **训练排队制**：全机 CPU 串行，开训前在 `coordination/mailbox-E.md` 登记（会话名/任务/步数/预计分钟），主 E 确认后执行。**AG-1 优先级最高**（主训练链），AG-2 数据采集可与训练并行（低 CPU），AG-3 排在 AG-1 阶段间隙。
3. 训练命令模板（防覆盖+检查点已内置）：
   ```
   cd rl_train && python train_jsbsim.py --task <task> --steps <N> --n-envs 4 \
     --lr 1e-4 --ent-coef 0.01 --seed 123 --checkpoint-every 250000 \
     [--init-model results/<父模型>.zip]
   ```
4. **训练由会话自己跑可以**（Antigravity 会话生命周期长于豆包），但每 30 分钟 tail 检查点是否推进；若进程死亡立即报告 mailbox-E 并断点续跑（从最新检查点 --init-model 续）。
5. 产物纪律：canonical 名被占用自动改时间戳名（覆盖保护已内置）；**禁止删改 results/ 任何现有文件**；每完成一个阶段 git commit。
6. G2 验收协议：5 种子（42/123/7/0/99）× 20 回合确定性评估；验收线 ≥85% 且 0 坠毁；内控线 ≥90% 且 0 坠毁。
7. 汇报：每阶段完成追加 `coordination/mailbox-E.md`（结论+数字+证据路径），等主 E 终审再进下一阶段。

## T1 主训练链（AG-1 会话，串行约 6~10 小时纯训练）

**阶段 0：helispike 环境接线与冒烟（约 1 小时）**
- 把 `rl_train/helispike_env.py` 接入 `train_jsbsim.make_env`（注册任务名 `heli_hover`/`heli_takeoff`/`heli_landing`），冒烟：每任务 3 回合随机策略 obs/reward 有限且在界内（参考 LandingTask 的出口消毒模式：nan_to_num+clip±10、reward clip±100——必须带，helispike dt=0.005 数值更敏感）。
- 关键参数（契约 v1.1）：dt=0.005（200Hz，训练吞吐约为 AH-1S 的 1/4，步数预算要放大）、coll 0.50=现稳态悬停点（0.70 待 0.2 标定）、roll_sign=+1、r 角速度用 psi 差分提取（r-radps 死属性）、train_config 里记录 `physics: helispike-0.2-WIP`。

**阶段 1：heli_hover 基线（2M 步，约 2~3 小时）**
- 从零训练（新物理没有可迁移父模型；一代 hover 权重维度不匹配不强行迁移）。
- 判据：定高误差、漂移、航向三门全过（阈值沿 v5.2 家族：漂移<20m、航向<20°）。
- 产物：`jsbsim_ppo_heli_hover_v1.zip` + `_results.json` + `_trajectory.json`。

**阶段 2：heli_takeoff（1.5M 步，从 hover 迁移）**
- 判据：地面→14m、漂移<30m、航向<45°、roll/pitch<15°。
- **重点观察**：helispike 有内建配平表（无自旋），航向偏差预期应显著优于一代（一代 6.1°，二代目标 <5°）——这是"自研 FDM 根治自旋"假设的第一个实证点，数字如实报。

**阶段 3：heli_landing（2M 步，从 hover 迁移）**
- 判据：软接地 vs≥-1.2m/s（剖面目标+20%容差）、接地水平速<1.0、漂移<30m、航向<45°、近地慢降。
- 注意：着陆科目受 B 0.2-WIP 包络限制（下降剖面只在悬停~低速可信区），如实记录。

**阶段 4：heli_forward（1M 步，受限包络）**
- 目标速度按 B 实测包络设 8kt（0.2-WIP 前飞上限 9.5kt）；jsbsim 升级后再扩 30kt。
- 判据：速度误差、高度带保持。

**阶段 5：heli_roll / heli_yaw / heli_waypoint（各 1~1.5M 步）**
- roll/yaw 沿一代判据；waypoint 双口径（单点+全任务 3 航点，强 course_phase=2 评估探针）——二代航向物理修复后 waypoint 全任务率是重点验证假设（一代卡 48.4%）。

**阶段 6：二代套件刷新 + live 演示**
- 全科目达标后由主 E 跑 `build_suite_report.py`（二代版）+ G4 闸门 + show_demo mp4（fdm=null 回放路径）。

## T2 操纵数据时长积累（AG-2 会话，与训练并行，低 CPU）

**目标**：验收第 2 条"操纵数据有效时长 ≥1000h"的数据积累启动（K6 工单）。
1. 用一代已闭环策略（takeoff_hard 98%/landing_gold 88%/hover 100%/forward/roll）批量跑确定性回合，录制每步操纵量+状态（双视角=座舱视图+外部视图的截图流可后补，先积累数据流）。
2. 每回合 20~40s，单核可 3~4 并行与训练共存；数据落 `rl_train/data/maneuver_dataset/`（jsonl 增量，字段=时间戳/科目/策略版本/逐帧 state+action+reward），每 100 回合一个分片文件+质检报告（NaN 率、末态成功率、时长累计）。
3. 质检口径沿验收表：有效时长=策略成功回合的飞行时长累计；失败回合记无效但留档。
4. 日报告：`data/maneuver_dataset/REPORT.md`（累计小时数、分科目分布、质检通过率），追加 mailbox-E。

## T3 超参扫描与消融（AG-3 会话，排队执行）

- 网格（heli_hover 上）：lr {5e-5, 1e-4, 3e-4} × ent_coef {0.005, 0.01}，每组合 1M 步+G2 简评（3 种子×20）。
- 消融项：γ 0.99 vs 0.995（waypoint 类长视野准备）；checkpoint 择优 vs 末态（量化检查点机制收益，为方法论报告补数据）。
- 全部结果落 `rl_train/results/sweep/` + 汇总表 `sweep_summary.md`；最优配置报 E 批复后用于 T1 后续科目。

## T4 里程碑与验收（主 E 把守）

- M-G1：heli_hover ≥90% → M-G2：takeoff+landing ≥85%/0 坠毁 → M-G3：四科目套件 ≥85% → M-G4：全七科目 + live mp4 → **二代验收闭环**。
- 每个里程碑主 E 终审后在决策台账记账；二代闭环后刷新验收第 5 条口径并同步 F 重建网站。

## 风险与止损

- helispike 0.2-WIP 数值死结（前飞>9.5kt）不阻塞 hover/takeoff/landing，但 forward/waypoint 结果要标注包络限制。
- 训练中遇 NaN 崩溃：出口消毒应已兜底；若仍崩，保留日志+检查点报 E，不要盲目重试第三次。
- 任何"改环境/改判据/改物理"的冲动：先写 issue 报 E，禁止直接动手（铁律 2/4）。
